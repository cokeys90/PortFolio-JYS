## 1. 블로그

- **목표**: 기술 회고·프로젝트 후기를 쓰는 공간 (`/blog`, `/blog/:slug`)
- **현재 상태**: 라우트만 있고 "추후 작업" 안내 문구만 표시
- **정할 것**
  - 글 저장 방식: ① 저장소 안 Markdown 파일(정적 빌드, 무료·단순) ② Firestore(관리자에서 작성)
  - 글 톤: 기술 회고 위주 / 프로젝트 후기 위주 / 둘 다 (`protfolio-plan.md` §11 미정 사항)
  - 첫 글 주제
- **구현 메모**
  - 렌더: react-markdown + remark-gfm + rehype-highlight (기존 계획 스택)
  - 디자인: 리뉴얼 톤(크림·네이비, 영문 제목 + 한글 본문) 그대로 적용, 읽기 폭 `max-w-3xl`
  - 내비에 "블로그" 메뉴 추가 여부 결정

## 2. 방문자 분석

- **목표**: 방문 수, 유입 경로, 지역(국가/도시), 많이 본 섹션 확인
- **필수 규칙** (CLAUDE.md 개인정보 처리)
  - 원본 IP 저장 금지 — 저장한다면 `SHA-256(ip + salt)` 해시만
  - 위치는 국가/지역/도시까지, 위경도 저장 금지
  - 첫 방문 고지 배너 1회 (localStorage)
- **현재 결정 사항** (`protfolio-plan.md` §10): Spark(무료) 플랜만 사용, Cloud Functions 사용 안 함 → 클라이언트에서 Firestore 직접 기록 + Firebase Analytics
- **보안**: App Check(reCAPTCHA v3) + Firestore 규칙 (`docs/safeguards.md`), 규칙 변경 시 emulator 검증 후 배포
- **주의**: Spark 일일 쓰기 한도(약 2만 건) 초과 위험 → 세션당 1건 기록 등으로 제한

## 3. 관리자 페이지

- **목표**: 방문자 통계 대시보드 + (블로그를 Firestore로 하면) 글 작성·수정·삭제
- **구현 메모**
  - Firebase Auth (본인 계정 1개만 허용) + `AdminRoute` 가드
  - 차트: Recharts, 지도: react-simple-maps (기존 계획 스택) — 관리자 페이지에서만 lazy 로드
  - 공개 사이트 번들에 관리자 코드가 섞이지 않도록 라우트 단위 분리
